## Commands

```sh
uv sync                     # install (use --locked to match CI)
mise run check              # format, lint, typecheck, pytest (the pre-commit gate)
uv run pytest               # tests
uv run pytest tests/test_logs.py::test_get_step_logs_returns_decoded_plain_text
mise run build              # podman build + run locally against .env (read-only, cap-drop ALL)
```

CI additionally runs `uv run vulture . --exclude "*settings.py,*/docs/*.py,*/test_*.py,*/.venv/*.py" --min-confidence 100`, which `mise run check` does not.

`pytest` runs with `asyncio_mode = "auto"`, so async tests need no marker.

The MCP Inspector tests need `bun` and Node >= 22.19 (both in `mise.toml`). Without them they skip locally; with `CI` set they run and fail instead, so a broken CI setup cannot hide them. The CI `pytest` job installs only those two through `mise-action` (`install_args: bun node`).

`mise run build` pulls from `dhi.io`, which requires `docker/podman login dhi.io` first.

## Architecture

An MCP server for Woodpecker CI. The tool surface is generated by `FastMCP.from_openapi` from a **vendored** copy of the Woodpecker OpenAPI spec (`src/woodpecker_mcp/openapi.yaml`, ~4.7k lines), narrowed by an allowlist.

Built on fastmcp 4 / MCP Python SDK v2, which use `httpx2` (not `httpx`) for all HTTP types. One server negotiates the protocol per client: modern (`2026-07-28`) clients get sessionless, self-contained requests; older clients get the legacy `initialize` handshake. Server-initiated sampling and roots do not exist in fastmcp 4, and `ctx.elicit()` works only for legacy clients.

`__main__` runs http with `stateless_http=True`, so legacy clients also get no `Mcp-Session-Id` and no standalone GET SSE stream; any replica can answer any request. Do not add features that need a server session (legacy `ctx.elicit()`, server-push notifications, `session_idle_timeout`).

`create_server` passes the installed package version (`importlib.metadata.version("woodpecker-ci-mcp")`) to fastmcp, so `serverInfo.version` is the package version, not fastmcp's.

Wiring lives in `server.py::create_server`: one `httpx2.AsyncClient` (base URL `<server>/api`) → `WoodpeckerAuth` → `RedactingTransport` → real transport; the prepared spec plus that client go into `FastMCP.from_openapi`, then `register_log_tool` adds the one hand-written tool.

### spec.py: the allowlist is the source of truth

`TOOLS: dict[(method, path) -> Tool(name, write)]` defines everything exposed. `prepare_spec` rebuilds `paths` from it, so unlisted routes simply don't exist; `read_only=True` drops the `write=True` entries. **To add or rename a tool, edit `TOOLS`**; the `operationId` it sets becomes the MCP tool name.

Two deliberate mutations in `prepare_spec`:
- `responses[*].content` is stripped from every operation. The upstream spec misdescribes responses (nil slices arrive as `null`, some handlers annotated `{array}` return an object), and fastmcp would fail output validation against them. Do not reinstate response schemas.
- `authorization` parameters are removed so the token never becomes a tool argument.

`tests/test_spec.py` and `tests/test_server.py` assert the exposed tool set equals `TOOLS` (plus `get_step_logs`) exactly, in both normal and read-only mode. Adding an entry to `TOOLS` needs no test change; if those assertions start failing, the tool surface drifted.

### auth.py: per-request token forwarding

Under http, each client sends its own `Authorization: Bearer <token>`; `WoodpeckerAuth.auth_flow` reads it per request via fastmcp's `get_http_headers` and sets it on the upstream request, so the shared `AsyncClient` never holds one client's credentials. `settings.token` (`WOODPECKER_TOKEN`) is only a fallback, and is mandatory under stdio (no request headers there). No token and no fallback → `MissingTokenError`.

Never move the token onto the client's default headers; that would leak it across clients.

### redact.py: transport-level scrubbing

`RedactingTransport` rewrites JSON responses, replacing any string-valued `token` key with `[REDACTED]` (Woodpecker returns agent registration tokens in cleartext to admin PATs). It sits at the transport so every tool (generated or hand-written) is covered.

### logs.py: the one hand-written tool

`get_step_logs` exists because the generated pass-through would return unbounded base64 line blobs. It decodes to plain text and tails (default 200 lines). Both the body and individual `data` fields may be `null` for purged logs.

### Testing seam

`create_server(settings, transport=...)` takes an `httpx2.AsyncBaseTransport`; tests pass `httpx2.MockTransport` and drive the server through a real `fastmcp.Client`. That injected transport is wrapped by `RedactingTransport`, so redaction is exercised too.

Most tests connect the `Client` in-process and monkeypatch `woodpecker_mcp.auth.get_http_headers` to fake caller headers. `tests/test_http.py` instead serves `mcp.http_app()` with uvicorn on a pre-bound loopback socket and connects with `BearerAuth`, once per protocol era (`mode="auto"` → modern, `mode="legacy"` → legacy). `serve()` builds the app with `stateless_http=True` to match production; `test_main.py` asserts production passes it. `test_legacy_client_needs_no_session_affinity_across_replicas` initializes against one app and calls a tool on another with raw JSON-RPC. With the Inspector tests below, these are the only coverage of real header forwarding (concurrent callers only here), so keep both eras parametrized.

The `test_inspector_*` tests run the MCP Inspector CLI (`bunx @modelcontextprotocol/inspector@INSPECTOR_VERSION --cli`) as a subprocess against `serve()`, once per era (`--protocol-era legacy|modern`). They are the only coverage with a non-Python client (TypeScript SDK): `initialize`, `tools/list --strict` (exit 6 on a schema portability error), and `tools/call` with and without a bearer token (exit 5 on a tool error). On a non-zero exit the Inspector prints a JSON error envelope as the last stderr line; `inspect()` parses that instead of stdout. `INSPECTOR_VERSION` carries a `# renovate:` comment that a custom manager in `renovate.json` matches; keep the comment immediately above it.

`serve()` in that file resets `sse_starlette.sse.AppStatus.should_exit` after each shutdown. The flag is process-wide; after a uvicorn shutdown it can stay `True`, and every later legacy SSE response then ends empty ("SSE stream ended without a response"). Production runs one app per process and is unaffected.

### Import-order constraint

`src/woodpecker_mcp/__init__.py` sets `FASTMCP_CHECK_FOR_UPDATES=off` before anything imports fastmcp, whose settings are read once at import time. Keep that statement first in the package.

## Release

`.github/workflows/release.yaml` runs release-please on every push to `main`. It keeps one open release PR that bumps `pyproject.toml`, the package entry in `uv.lock` (an `extra-files` TOML updater in `release-please-config.json`) and `CHANGELOG.md`. Nothing is released until that PR is merged. The merge creates the `v<version>` tag and GitHub release, then `publish.yaml` pushes to ghcr.io and the `pypi` job publishes `woodpecker-ci-mcp` via trusted publishing. `publish.yaml` **fails unless the tag (minus `v`) equals `project.version`**.

Do not bump versions by hand; release-please derives them from Conventional Commits and tracks the current one in `.release-please-manifest.json`. `cog` is kept only for `cog check` in CI.

## Versions

fastmcp is `>=4.1.0`. 4.1.0 rejects `.`/`..` OpenAPI path segments, sends only declared OpenAPI arguments, surfaces upstream HTTP errors as HTTP status errors, and expires idle legacy HTTP sessions after 30 minutes.

`requires-python = ">=3.13"`, but `.python-version` and the Dockerfile's `PYTHON_VERSION` arg are both `3.14`; keep those two in sync. Dockerfile `ARG`s carry `# renovate:` comments that a custom manager in `renovate.json` matches; keep the comment immediately above the `ARG` line.
